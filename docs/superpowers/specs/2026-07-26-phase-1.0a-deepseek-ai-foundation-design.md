# Phase 1.0A — DeepSeek AI foundation

Status: contract frozen for implementation
Date: 2026-07-26
Provider: DeepSeek
Credential model: BYOK

## Outcome

Phase 1.0A establishes a secure provider runtime and one deliberately narrow
product flow:

1. Save a user-entered DeepSeek key in Windows Credential Manager.
2. Test `/models` and `/user/balance`.
3. Select a model returned by `/models`.
4. Stream a StoryForge test response through a per-job Tauri Channel.
5. Cancel a generation.
6. Display anonymous token usage.
7. Restart without persisting the prompt or response.
8. Delete the credential and cancel any active DeepSeek job.

AI output is candidate text only. It cannot write a chapter, reference,
timeline, review state, backup or version.

## Official API baseline

- Base URL: `https://api.deepseek.com`
- Models: `GET /models`
- Balance: `GET /user/balance`
- Chat: `POST /chat/completions`
- Runtime model identifiers: `deepseek-v4-flash` and `deepseek-v4-pro`
- Legacy identifiers `deepseek-chat` and `deepseek-reasoner` are not accepted
  by the Phase 1.0A adapter.
- Non-thinking mode is explicit: `thinking.type = disabled`.
- Streaming requests set `stream = true` and
  `stream_options.include_usage = true`.

References:

- [List models](https://api-docs.deepseek.com/api/list-models)
- [Create chat completion](https://api-docs.deepseek.com/api/create-chat-completion)
- [Get user balance](https://api-docs.deepseek.com/api/get-user-balance/)
- [Thinking mode](https://api-docs.deepseek.com/guides/thinking_mode)
- [DeepSeek V4 change log](https://api-docs.deepseek.com/updates/)

The returned `/models` list is the runtime source of truth. The local default
is only a selection preference.

## Trust boundaries

```text
React UI → application/store → AI core → platform port ← Rust adapters
                                                   ↓
                                  fixed DeepSeek HTTPS allowlist
```

- React cannot issue DeepSeek HTTP requests.
- React cannot read a saved credential.
- The base URL is not configurable.
- Project paths and project content are absent from every Phase 1.0A request.
- Prompt, response and reasoning content are absent from settings, usage,
  logs, diagnostics, projects, snapshots and backups.
- The Rust adapter discards `reasoning_content`; the UI receives only a
  `thinking_started` state event.

## Public contracts

The AI core owns provider definitions, preferences, request/event/error types,
model selection, job transitions, retry decisions and usage aggregation.
Platform ports expose typed scoped operations. Rust owns:

- exact Credential Manager target `WritingBuddy/AI/DeepSeek/default`;
- fixed-host HTTPS transport with redirects disabled;
- SSE framing and UTF-8 buffering;
- cancellation registry and timeouts;
- non-sensitive settings/model cache/usage files;
- public error serialization and redacted audit fields.

One active job is allowed. Starting another job cancels the active job before
starting the replacement. The internal queue contract is capped at three, but
the Phase 1.0A UI uses replace-current behavior.

## Streaming rules

- Accept LF and CRLF.
- Ignore blank frames and `:` comments.
- Accept usage-only chunks and `null` content.
- Never forward raw reasoning.
- Require `data: [DONE]`; EOF first is `stream_incomplete`.
- Invalid UTF-8 or JSON is `stream_parse_failed`.
- Content deltas are coalesced before UI delivery.
- Cancellation aborts the HTTP body, emits `cancelled` once and never retries.

## Retry and timeout policy

- Connect: 15 seconds.
- First actual content: 180 seconds; keep-alive does not reset it.
- Stream idle after content: 120 seconds.
- Hard job limit: 10 minutes.
- Retry at most twice, only before meaningful streamed data, for transport,
  429, 500 and 503 failures.
- Backoff: approximately 1 second, then 3 seconds, with bounded jitter.
- Never retry authentication, balance, request, parse, cancellation or any
  failure after content.

## Persistence

Under the Tauri application data directory:

- `settings/ai.json`: non-sensitive preferences and credential metadata.
- `ai/provider-model-cache.json`: model identifiers, 24-hour TTL.
- `ai/usage/YYYY-MM.jsonl`: timestamp, provider/model/job type, token counts,
  duration and terminal status only.

No project-local AI settings are created by Phase 1.0A.

## Completion boundary

Automated completion requires TypeScript, React and Rust tests plus a packaged
desktop smoke test. Real API completion additionally requires a user-provided
test credential and remains a manual gate. A production credential must never
be added to fixtures or automation.
