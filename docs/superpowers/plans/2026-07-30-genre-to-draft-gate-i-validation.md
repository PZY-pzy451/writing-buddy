# Gate I：Genre-to-Draft 核心旅程验证计划

## 目标

在不让 AI 直接改写作者大纲的前提下，为结构化故事大纲增加可解释、可定位、可重复执行的质量检查，并完成 Phase 1.2B 从新建项目到二次启动恢复的完整纵向验收。

## 实现边界

- 本地结构检查完全离线、确定性执行，覆盖空标题、空摘要、同级顺序重复、孤立节点、场景缺少章节、章节缺少卷、重复 ID、锁定节点被改动、章节计划状态与正文状态不一致。
- AI 语义检查通过现有 `creation-journey` AI 作业执行，只返回问题、证据、影响和建议动作；不得返回补丁，也不得修改节点。
- 本地错误和 AI 建议在界面上分组展示。打开“检查大纲”只运行本地规则；AI 检查必须由作者再次明确触发。
- 检查结果绑定大纲修订号；大纲变化后旧结果标记为过期，不自动重复调用 AI。
- 点击问题可定位到涉及节点；所有状态都使用文本和图标共同表达。

## 测试驱动顺序

1. 为纯函数检查器补充失败测试，覆盖九类本地规则、稳定问题 ID、锁定基线、正文状态映射和大规模节点性能。
2. 为 AI 请求/响应契约补充 TypeScript 与 Rust 对称测试，验证严格字段、未知节点、伪造证据、禁用系统路径/凭证字段和只读响应。
3. 为大纲工作区补充交互测试，验证本地检查不调用 AI、AI 明确触发、防重复点击、结果过期、问题定位和零自动改写。
4. 接入创作旅程页面与浏览器确定性 AI 夹具，补齐可访问标签、键盘焦点、小尺寸布局和 reduced-motion。
5. 运行聚焦测试、全量 lint/typecheck/test/build、自测框架、原生 Tauri smoke、浏览器完整纵向链。

## 验收证据

- 本地结构检查耗时与大规模节点基准。
- AI 契约的前后端对称测试和非法响应拒绝测试。
- 360px 级小尺寸无横向溢出、主要控件至少 44px、可见键盘焦点、语义区域与 live status。
- 完整纵向链：新建项目 → 类型与可选梗概 → 生成大纲 → 编辑/锁定 → 三候选 → 采纳 → 卷/章/场景 → 拖动场景 → 写作 → 引导续写 → 插入/拒绝 → Undo → 章节整理 → 计划/实际对比 → 作者选择更新 → 重启恢复。
- 可运行 portable 与 setup EXE 的 SHA-256 校验值。
