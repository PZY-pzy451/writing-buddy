# Phase 1.2C — AI Draft Insertion Experience

Date: 2026-07-30

Baseline: `dc872efb test: validate genre to draft core journey`

## Frozen first-round scope

Deliver only the shortest author-controlled path:

- continue at the current cursor;
- polish and replace the current selection;
- show the generated result as an editable inline pending draft;
- write or discard the pending draft;
- create a canonical safety snapshot before mutation;
- commit the draft through one Monaco edit transaction;
- autosave after the edit;
- make one native `Ctrl+Z` undo the complete AI edit.

Whole-scene/chapter generation, partial-paragraph adoption, three-direction
guided generation, persisted restart recovery, and automatic TextAnchor
relocation remain outside this round.

## Existing seams

- `ManuscriptContinuationPanel` and `SelectionRewritePanel` already own
  grounded generation and strict response parsing.
- `ChapterEditor` already tracks exact cursor/selection offsets and owns the
  Monaco instance.
- `DocumentSession.state.version` is the authoritative in-memory document
  revision.
- `desktopBridge.createSnapshot(..., 'beforeDestructiveOperation', ...)` is
  the canonical pre-write snapshot path.
- `ChapterEditor` already applies queued edits with
  `pushUndoStop → executeEdits → pushUndoStop`.
- `useAppStore.save()` is the existing atomic manuscript save path and word
  count is updated only after it succeeds.

## Data boundary

Add a transient application-level `PendingDraftCandidate` that is deliberately
separate from the Monaco model and persisted manuscript:

- stable candidate/action/resource identifiers;
- insertion target mode, offsets, base revision, and before/after anchors;
- generated and currently edited content;
- target/context summaries;
- ready/edited/applying/applied/discarded/failed status.

The candidate is not included in `DocumentSession.content`, word counts,
autosave payloads, or the persisted workspace. It is visible only through a
Monaco view zone hosted by React.

## Target resolver

The first round resolves exactly two modes:

- `insert_at_cursor`: zero-length range at the captured cursor;
- `replace_selection`: captured non-empty selection range.

Creation clamps offsets and captures bounded anchors. Commit requires the same
resource, exact document revision, valid range, and exact anchors. A changed
document makes the candidate stale and disables write. No blind insertion or
implicit relocation is permitted in this round.

## Generation handoff

On a successful non-direction continuation or selection rewrite:

1. construct the pending candidate from the parsed AI result;
2. place it in the shared transient store;
3. render it inside the editor at the captured target line;
4. keep the assistant as context/generation history only;
5. make the inline card the only place that can edit, write, or discard it.

Generating a new candidate replaces the previous uncommitted candidate only
after the new response is valid.

## Commit transaction

The editor owns the commit because it is the only layer with the live Monaco
model:

1. reject read-only, wrong-resource, stale-revision, invalid-range, empty-text,
   or anchor-mismatch candidates;
2. save any dirty pre-commit manuscript and verify the resource/content did
   not change;
3. create a canonical `beforeDestructiveOperation` snapshot;
4. revalidate content and target;
5. call one `executeEdits` operation surrounded by two undo stops;
6. autosave and verify a clean save state;
7. clear the pending card and show a lightweight success/Undo notice.

A save-induced session-version increment is allowed only when manuscript
content and anchors remain byte-for-byte equivalent. Any author edit or
external conflict blocks the commit.

## UI contract

- warm-gold left border and paper-toned surface;
- “AI 临时草稿” label, exact target summary, and bounded context summary;
- editable textarea before commit;
- “写入正文” as the only primary action and “丢弃” as secondary;
- stale/error state is visible and never writes;
- controls are at least 44 px, keyboard reachable, focus-visible, and do not
  create horizontal overflow;
- reduced motion disables nonessential transition/highlight animation.

3. Update continuation and rewrite tests to prove successful generation hands
