# Phase 1.0A implementation plan

## 1. Contract and source map

- Freeze official endpoints, model identifiers and security boundaries.
- Map current AI, settings, bridge, Rust secret and HTTP code.
- Remove the old non-streaming selection rewrite network path.

## 2. AI core

- Add provider registry and DeepSeek definition.
- Add preferences, request, stream event, usage and public error models.
- Add deterministic model selection, state transitions, retry policy and
  usage aggregation.
- Preserve the local fake provider used by existing selection-review tests.

## 3. Platform ports and application state

- Replace generic `aiComplete` with scoped status, credential, model, balance,
  preferences, generation, cancellation and usage methods.
- Add an in-memory AI job store; persist only through Rust preferences/usage.
- Provide a browser fixture adapter for React tests and visual preview.

## 4. Rust adapters

- Implement exact Windows Credential Manager target and short fingerprint.
- Implement settings, model cache and monthly JSONL usage.
- Implement fixed DeepSeek client, HTTP status mapping and redirect denial.
- Implement incremental SSE parser, usage chunks and reasoning redaction.
- Implement one-active-job cancellation registry and Tauri Channel command.

## 5. React UI

- Add Settings tabs for Appearance and AI & Models.
- Add DeepSeek provider/model/usage cards with labelled controls, visible
  focus, 44-pixel actions and explicit loading/error states.
- Add a StoryForge rail page with stream, stop, copy and clear actions.
- Keep prompt/result in memory across page switches, never in persisted store.

## 6. Hardening and acceptance

- TypeScript compile before focused and full tests.
- Rust mock transport/SSE/secret metadata tests without a real key.
- Search staged/repository output for secrets and forbidden log fields.
- Build Vite and packaged Tauri artifacts.
- Record automated evidence and leave real API flow open for manual execution.
